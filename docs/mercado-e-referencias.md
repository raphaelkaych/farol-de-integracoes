# Mercado e decisões para o portfólio

Consulta em 6 de novembro de 2026. A amostra foi escolhida para cobrir cinco vagas brasileiras de entrada em QA, full stack, backend e análise de sistemas. Dois anúncios internacionais ajudam a identificar práticas que ganham profundidade com a senioridade. Os anúncios descrevem funções específicas e a amostra tem alcance qualitativo.

## O que os dados de 2026 medem

- **Octoverse.** No GitHub, TypeScript, Python e JavaScript lideraram nessa ordem por número de contribuidores. O relatório também registra aumento do uso de GitHub Actions. A unidade de análise é a atividade na plataforma no período de outubro de 2025 a setembro de 2026. [GitHub Octoverse 2026](https://github.blog/news-insights/octoverse/octoverse-commits-pushes-reach-new-highs-in-2026-as-developers-build-with-agents/)
- **Stack Overflow.** Entre as 14.099 respostas à pergunta sobre uso de linguagens, 62% indicaram JavaScript, 58,4% SQL, 58% Python e 43,8% TypeScript. Na pergunta sobre desenvolvimento com tecnologias web, com 10.281 respostas, Node.js registrou 46,4%, React 41,5% e Next.js 20,6%. PostgreSQL liderou a pergunta sobre bancos de dados, com 57,9%, e SQLite teve 42,1%. São respostas autodeclaradas, com possibilidade de múltiplas escolhas por pergunta. [Metodologia](https://survey.stackoverflow.co/2026/methodology), [Linguagens](https://survey.stackoverflow.co/2026/technology/data/languages), [Tecnologias web](https://survey.stackoverflow.co/2026/technology/data/web-framework), [Bancos de dados](https://survey.stackoverflow.co/2026/technology)
- **IA na engenharia.** A pesquisa relata que parte dos respondentes confia mais na IA quando consegue verificar o resultado. A Cuattro explicita essa prática na vaga, ao pedir revisão, teste e validação crítica. No portfólio, isso se traduz em conferir o comportamento com testes e tratar dados fictícios como dados de demonstração. [Stack Overflow · IA](https://survey.stackoverflow.co/2026/ai), [Cuattro · Full Stack Júnior](https://cuattro.gupy.io/jobs/12060018?jobBoardSource=gupy_public_page)

Os relatórios medem atividade no GitHub e uso declarado por respondentes, respectivamente. As vagas são a evidência direta sobre o que os empregadores da amostra pedem.

## Decisões para este portfólio

| Foco | Evidência a apresentar |
| --- | --- |
| Full stack e dados | Usar React e TypeScript para interfaces e contratos tipados. Demonstrar SQL com restrições, migrações e consultas explicáveis. D1 oferece semântica SQLite no ambiente publicado. PostgreSQL aparece como referência de mercado e faz sentido como ambiente separado quando houver um caso que o justifique. [Cloudflare D1](https://developers.cloudflare.com/d1/) |
| Backend e integração | Mostrar entradas válidas e inválidas, respostas HTTP previstas, reenvios, deduplicação e recuperação a partir do histórico. Contratos OpenAPI descrevem o que um consumidor pode enviar e receber. Os testes de integração comparam esse contrato com o comportamento do serviço. [OpenAPI Specification](https://spec.openapis.org/oas/latest.html) |
| QA e entrega | Cobrir regras do domínio com testes rápidos, validar banco e contratos na integração e reservar Playwright para jornadas de interface e cenários críticos de API. Dar preferência a seletores por papel ou rótulo, isolar o estado de cada teste e associar screenshots e traces ao run real de CI. Vitest atende suítes TypeScript. Para Python, pytest é uma opção quando o projeto precisar de fixtures e parametrização além da suíte atual. [Playwright · Boas práticas](https://playwright.dev/docs/best-practices), [Playwright · CI](https://playwright.dev/docs/ci), [Vitest](https://vitest.dev/guide/), [pytest](https://docs.pytest.org/en/stable/) |
| Reprodutibilidade | Descrever versões, dependências travadas, comandos e dados de exemplo. GitHub Actions torna o resultado de cada revisão consultável. Docker Compose é uma opção útil quando a reprodução precisa iniciar vários serviços, como API e PostgreSQL. [Playwright · CI](https://playwright.dev/docs/ci), [Docker Compose](https://docs.docker.com/compose/) |
| Segurança e observabilidade | Testar acesso a registros de outra sessão e os limites de entradas e operações onde forem aplicáveis. Mostrar decisões e erros com identificadores correlacionáveis, diferenciando eventos simulados de telemetria capturada. O OWASP API Security Top 10 orienta a escolha de cenários. A documentação do OpenTelemetry distingue métricas, logs e traces. [OWASP API Security Top 10](https://api-security.owasp.org/editions/2023/en/0x11-t10/), [OpenTelemetry · Signals](https://opentelemetry.io/docs/concepts/signals/) |
| Acessibilidade e performance | Validar foco visível e desobstruído, contraste, navegação por teclado e estados de formulário. Reservar espaço para o hero e respeitar movimento reduzido. Para Core Web Vitals, os alvos de campo são LCP de até 2,5 s, INP de até 200 ms e CLS de até 0,1 no percentil 75. Identificar medições de laboratório pelo ambiente e pela rota testada. [WCAG 2.2](https://www.w3.org/TR/WCAG22/), [web.dev · Web Vitals](https://web.dev/articles/vitals) |

Um caso de integração pode mostrar o percurso de uma falha até a recuperação. Um caso de QA pode mostrar o cenário, o resultado esperado, a falha controlada e o teste que a detecta. Juntos, eles conectam a trajetória de sustentação de sistemas a evidências de desenvolvimento e qualidade de software.
